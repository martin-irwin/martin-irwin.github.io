# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Source for **kuroshi.net** (`CNAME`): a personal Jekyll 3.10 blog (400+ posts since 2012) plus a handful of standalone tool/catalogue pages. There is no test suite or linter.

## Commands

```bash
bundle install
bundle exec jekyll serve          # local preview at http://localhost:4000
bundle exec jekyll serve -l       # with livereload (same as `rake build`)
bundle exec jekyll build          # output to _site/
```

Jekyll 3.10 on Ruby 3.4+ fails with `cannot load such file -- base64` (then `erb`, etc.): those gems left the standard library. Production doesn't care (Pages builds with its own Ruby), so to build locally without touching the repo, copy `Gemfile` elsewhere, append `base64 bigdecimal csv logger ostruct erb json drb mutex_m`, and run with `BUNDLE_GEMFILE=<copy>`. A `Dockerfile` + `.devcontainer/` exist as an alternative.

**Deploy:** pushing to `main` deploys via `.github/workflows/jekyll.yml`, which uses `actions/jekyll-build-pages` (the GitHub Pages builder), **not** the local `Gemfile`. Only plugins on the GitHub Pages allowlist work in production; `_config.yml` lists `jekyll-sitemap`, `jekyll-feed`, `jekyll-include-cache`. `future: true` is set, so future-dated posts publish immediately.

## Architecture

### Layouts: `pure` is the real site
`_config.yml` defaults every post and page to `_layouts/pure.html`. It is self-contained: all CSS is inline in the layout (monospace, `#f2f2f2` background, 600px column, dotted-underline links), no external stylesheet, and a small script that wraps every `main img` in a link to itself. It renders `page.header.image` as the featured image, adds a "Get in touch" footer only for posts with category `blog`, and a `../` back link.

Most of `_layouts/`, `_includes/` and `_sass/minimal-mistakes/` are leftovers from the old Minimal Mistakes theme. Only a few legacy pages still use them (`_pages/404.md`, `_pages/blog.md`, `categories.html`, `tags.html`, `tag.html` via `archive`/`default`/`home`). Don't restyle the site through `_sass/` or `assets/css/main.scss`; `pure` doesn't load them. Some MM includes are still used from post bodies, notably `{% include gallery id="..." layout="half|third" %}`, which reads an image list from the post's front matter.

**Pigment** (ported from the terminus.events landing page): `_includes/pigment-head.html` sits in `pure`'s `<head>` and sets `--pigment` (accent that reads on the light page), `--n-bg` / `--n-fg` (fill and text on it) before first paint, from `localStorage['k-pigment']`, defaulting to `graphite` (≈ the original black). `_includes/pigment.html` is the fixed bottom-right swatch row. Colour site accents with `var(--pigment, #000)`, not hard-coded black. The `layout: null` pages don't get it.

**Look "01"** (after 37signals.com/01): the "01" button in the swatch row sets `html[data-look="01"]` (saved as `k-look`; the head script applies it before paint and only then loads Schibsted Grotesk from Google Fonts). All of it is CSS under `html[data-look="01"]` in `pure.html`: `--ink`/`--paper` become the pigment's `--n-fg`/`--n-bg`, so the page floods with the pigment; post titles get their index number (`post_no`, computed in the layout's front Liquid, same numbering as the home list) with the body hung under the title; index titles are hidden until hovered on fine-pointer devices, always shown on touch. Use `var(--ink)` / `var(--paper)` instead of hard-coded `#000` / `#f2f2f2` in pages, or they vanish in 01.

`index.html` (latest 10 posts) and `posts.md` (`/posts/`, all posts) build the numbered, lowercase post lists.

### Posts
`_posts/YYYY-MM-DD-slug.md`. Typical front matter: `title`, `excerpt`, `date`, `tags`, `categories: [blog]`, `header.image` / `teaser` / `og_image`, and named gallery arrays (`foo_gallery: [{url, image_path, alt}]`). Images go in `assets/images/`. Some filenames contain spaces; quote paths in shell commands.

### Standalone pages (`_pages/`, `layout: null`)
These are full HTML documents with their own `<head>`, CSS and JS, deliberately outside the site layout:
- `octane.html` → `/octane.html`: Swiss E85 / Shell V-Power 100 fuel-station finder (big single-file app). It loads `assets/data/vpower-stations.json`, which is regenerated by `node scripts/fetch-vpower.js` (Node 18+; there is also an older `fetch-vpower.sh` that needs `jq`). The JSON shape (`_meta` + `stations[]`) is a contract with `buildVpowerStation()` / `loadVpowerStations()` in the page; keep the script and the page in sync.
- `es-9dvd.html` → `/es-9dvd/`: English guide to the Kenwood ES-9DVD.
- `forsale-audis6.html` → `/forsale/audis6/`: German-language for-sale listing.
- `boox-calendar*.html`, `agrola-redirect.html`: small utilities.

### Data-driven MiniDisc catalogue
`_data/minidisc.yml` is the single source of truth (one entry per model; the field schema is documented in the file's header comment). It feeds both `_pages/minidisc.html` (`/minidisc/`, `pure` layout with inline client-side filters: owned/sold, type, etc.) and `_pages/minidisc.json` (`/minidisc.json` via `jsonify`). Photos go in `assets/minidisc/`. To add or change a unit, edit only the YAML.

### Other

- `japanese/` holds kanji-study notes plus raw exported Anki "Kanji Grid" HTML snapshots.

## Conventions
